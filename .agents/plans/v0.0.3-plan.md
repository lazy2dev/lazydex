## 1. Theme System Overhaul (Root Cause of UI Inconsistency)

Material3 needs a **complete** color scheme — currently both `DarkColorScheme` and `LightColorScheme` define only ~8 of ~20 required roles. Undefined roles fall back to Material defaults, causing visual inconsistency across screens.

### 1.1 Complete Both Color Schemes
- [ ] Audit `Theme.kt` — add all missing Material3 color roles to both schemes:
  - `onPrimary`, `onSecondary`, `onTertiary`, `tertiary`, `error`, `onError`
  - `onSurfaceVariant`, `surfaceVariant` (missing in light scheme)
  - `surfaceTint`, `inverseSurface`, `inverseOnSurface`, `inversePrimary`
  - `outlineVariant`, `scrim`
- [ ] Ensure `surfaceVariant` in light scheme — components using it (cards, bottom sheets) currently get default colors
- [ ] Match custom `Color.kt` values to the correct M3 semantic roles

### 1.2 Fix `dynamicColor` Wiring
- [ ] Wire `dynamicColor` preference from `AppearanceScreen` through `MainActivity` to `LazyDexTheme`
- [ ] Currently `dynamicColor` defaults to `true` with no user toggle — on Android 12+, system dynamic colors override custom scheme, creating half-custom/half-system look
- [ ] When `dynamicColor` is enabled AND user has custom scheme preference, define priority order

### 1.3 Replace Hardcoded Colors with Theme Tokens
- [ ] `MediaCard.kt` — `Color(0xFFF1C40F)` → `MaterialTheme.colorScheme.tertiary`
- [ ] `CoverImage.kt` — `Color(0xFF2C3E50)` gradient → theme-based fallback
- [ ] `StarRating.kt` — `Color.Gray` for unrated
- [ ] Audit every `Color(` usage in UI components
- [ ] Verify list view and grid view cards both use theme colors

### 1.4 Visual Audit Checklist

## 2. Performance — Fix at the Data Layer (Root Cause of Lag)

### 2.1 Push Filtering/Sorting to Room
- [ ] **Current**: `DexViewModel.kt:134-170` fetches ALL items, then in-memory `filter{}` + `sortItems()` on every combine cycle
- [ ] **Fix**: Replace with Room `@Query`:
  - `WHERE category IS NULL OR category = :category`
  - `WHERE userStatus IN (...)`
  - `ORDER BY dateAdded DESC` (already at DB level)
- [ ] Create dedicated DAO queries for composite filters

### 2.2 Replace Genre/Tag Scanning
- [ ] **Current**: `MediaRepositoryImpl.kt:86-102` calls `dao.observeAll()` / `observeByCategory()`, then iterates EVERY item to extract unique genres/tags
- [ ] **Fix**: Add Room queries with `SELECT DISTINCT` or add normalized genre/tag table
- [ ] Option A: Add `genres` and `tags` junction tables with FK to `media_items`
- [ ] Option B: Use SQLite `json_each()` to extract distinct values

### 2.3 Eliminate Flow Cascade
- [ ] **Problem**: One DB write → 6+ observers re-emit → full re-filter/re-sort chain
- [ ] **Fix**: Use `distinctUntilChanged()` strategically. Separate "list data" from "metadata" (genres/tags/counts) flows
- [ ] Only recompute what actually changed

### 2.4 Verify Dispatchers
- [ ] Check `flowOn(Dispatchers.Default)` in `DexViewModel.kt:170` — currently only affects upstream
- [ ] The `combine` lambda (filtering + sorting) must run on `Dispatchers.Default`, emit to main for collection

## 4. Learning Path

For each area, study the Kotlin/Compose concepts before coding:

| Area | Kotlin Concepts | Compose Concepts |
|------|----------------|------------------|
| Theme | Sealed classes, extension functions | `MaterialTheme`, `ColorScheme`, dynamic color APIs |
| Performance | Flow operators (`combine`, `flatMapLatest`, `flowOn`, `distinctUntilChanged`) | Recomposition scoping, `remember`, `derivedStateOf` |
| Room/SQL | Coroutines, `Flow`, `suspend` functions, `@Query` | — |
| Architecture | Interface segregation, DI with Koin | MVVM, state hoisting |

Study resources: Kotlin official docs, Android developer guides, Material3 guidelines.
